# \# 지금, 어디에 주차할까? 🅿️

# 

# 서울시 공영주차장의 \*\*혼잡도·요금·운영시간을 비교하고 길찾기까지 이어지는 지도형 대시보드\*\*입니다.

# 

# > \*\*지역의 혼잡도를 파악하고 → 실제 주차장을 비교하고 → 길찾기로 이동합니다.\*\*

# 

# 🔗 \*\*\[대시보드 바로 보기](https://hewa5318.github.io/parking-congestion-map/)\*\*

# 

# \---

# 

# \## 프로젝트 소개

# 

# 주차장을 찾을 때 필요한 정보는 한 가지가 아닙니다.

# 

# 어느 지역이 붐비는지,  

# 개별 주차장은 얼마나 찼는지,  

# 요금은 얼마인지,  

# 언제까지 운영하는지를 함께 확인해야 실제 선택으로 이어집니다.

# 

# 서울시 공영주차장 데이터에는 이런 정보가 제공되고 있었지만,  

# 각 정보를 사용자가 빠르게 비교하고 선택할 수 있는 흐름으로 묶는 작업이 필요했습니다.

# 

# 그래서 다음 질문에서 프로젝트를 시작했습니다.

# 

# > \*\*“지금 어느 지역이 붐비고, 실제로 어느 주차장을 선택하면 좋을까?”\*\*

# 

# \*\*개인 프로젝트 · 기획 / 데이터 수집·정제 / 지표 설계 / 시각화 / UI·UX 구현\*\*

# 

# \---

# 

# \## 어떻게 사용하나요?

# 

# \### 1. 서울 전체 상황 확인

# 

# 상단 KPI에서 총 주차면과 전체 혼잡도,  

# 여유·혼잡 상태의 주차장 수를 빠르게 확인합니다.

# 

# \### 2. 붐비는 지역 찾기

# 

# 자치구별 혼잡도를 막대그래프로 비교합니다.

# 

# 자치구 혼잡도는 주차장별 비율의 단순 평균이 아니라

# 

# \*\*자치구 내 현재 차량 수의 합 ÷ 전체 주차면의 합\*\*

# 

# 으로 계산해 주차장 규모가 반영되도록 했습니다.

# 

# \### 3. 실제 주차장 비교

# 

# 차트에서 자치구를 선택하면  

# 지도가 해당 지역으로 이동합니다.

# 

# 지도에서는 혼잡 상태를 색상으로 구분하고,  

# 주차장을 선택하면 다음 정보를 확인할 수 있습니다.

# 

# \- 현재 혼잡도

# \- 기본·추가·일 최대 요금

# \- 평일·주말 운영시간

# \- 해당 주차장의 최근 데이터 갱신시각

# 

# \### 4. 길찾기로 이동

# 

# 선택한 주차장에서  

# \*\*카카오맵 길찾기\*\*로 바로 이동할 수 있습니다.

# 

# \---

# 

# \## 핵심 기능

# 

# | 기능 | 설명 |

# |---|---|

# | 서울 전체 KPI | 총 주차면, 전체 혼잡도, 여유·혼잡 주차장 수 확인 |

# | 자치구별 혼잡도 | 지역별 주차 상황을 비교 |

# | 혼잡 상태 지도 | 여유·보통·주의·혼잡 상태를 마커 색으로 구분 |

# | 차트 ↔ 지도 연동 | 자치구 선택 시 지도가 해당 지역으로 이동 |

# | 주차장 상세 정보 | 혼잡도·요금·운영시간·갱신시각 제공 |

# | 카카오맵 길찾기 | 선택한 주차장을 목적지로 연결 |

# | 반응형 화면 | 화면 크기에 따라 KPI와 패널 배치 조정 |

# 

# \---

# 

# \## 데이터와 혼잡도 기준

# 

# 데이터는 \*\*서울 열린데이터광장 `GetParkingInfo` API\*\*를 사용했습니다.

# 

# 주요 사용 정보는 다음과 같습니다.

# 

# \- 주차장명과 주소

# \- 전체 주차면

# \- 현재 주차 차량 수

# \- 요금 정보

# \- 평일·주말 운영시간

# \- 최근 주차정보 갱신시각

# 

# \### 주차장 혼잡률

# 

# \*\*현재 주차 차량 수 ÷ 전체 주차면 × 100\*\*

# 

# | 혼잡률 | 상태 |

# |---:|---|

# | 0 \~ 35% 미만 | 여유 |

# | 35 \~ 70% 미만 | 보통 |

# | 70 \~ 90% 미만 | 주의 |

# | 90% 이상 | 혼잡 |

# | 계산 불가 | 정보없음 |

# 

# \---

# 

# \## 해결해야 했던 문제

# 

# \### 1. 지도에 쓸 좌표가 부족했습니다

# 

# 실시간 주차 API에는 주소가 있었지만  

# 지도에 바로 사용할 정상 위·경도가 없거나 결측인 항목이 있었습니다.

# 

# 그래서 Kakao Local API를 이용해

# 

# \*\*주소 검색 → 실패 시 키워드 검색\*\*

# 

# 순으로 위치를 보완했습니다.

# 

# 프로젝트 제작 당시 수집한 \*\*122개 주차장 중 107개의 좌표를 확보\*\*했고,  

# 서울 범위를 벗어난 좌표는 제외해 잘못된 위치가 지도에 표시되는 것을 줄였습니다.

# 

# \---

# 

# \### 2. 지역 혼잡도를 단순 평균으로 계산하지 않았습니다

# 

# 20면 규모의 주차장과 500면 규모의 주차장을  

# 같은 비중으로 평균하면 실제 지역 상황이 왜곡될 수 있습니다.

# 

# 그래서 자치구 혼잡도는

# 

# \*\*현재 차량 수의 합 ÷ 전체 주차면의 합\*\*

# 

# 으로 계산했습니다.

# 

# 큰 주차장의 규모가 자연스럽게 반영되는 방식입니다.

# 

# \---

# 

# \### 3. 정보가 많을수록 오히려 선택하기 어려웠습니다

# 

# 초기 지도 팝업에는

# 

# 주차면 수, 현재 차량 수, 잔여면, 월 정기권 등  

# 많은 정보를 한꺼번에 넣었습니다.

# 

# 하지만 실제 화면에서는 팝업이 지도를 크게 가리고  

# 중요한 정보가 무엇인지 빠르게 파악하기 어려웠습니다.

# 

# 그래서 실제 주차장 선택에 필요한 정보를 중심으로

# 

# \*\*혼잡도 → 요금 → 운영시간 → 길찾기\*\*

# 

# 순으로 다시 정리하고 팝업 크기도 줄였습니다.

# 

# \---

# 

# \### 4. 차트와 지도가 따로 움직이고 있었습니다

# 

# 자치구 차트에서 붐비는 지역을 찾은 뒤  

# 사용자가 지도에서 같은 지역을 다시 찾아야 했습니다.

# 

# 이를 줄이기 위해

# 

# \*\*차트의 막대나 자치구명을 선택하면  

# 지도가 해당 지역으로 확대되는 인터랙션\*\*

# 

# 을 추가했습니다.

# 

# 차트는 \*\*“어느 지역이 붐비는가”\*\*,  

# 지도는 \*\*“그 지역에서 어느 주차장을 선택할 것인가”\*\*를 담당하도록 역할을 나눴습니다.
